# Почему не удалось проверить реальную доставку

Проверка выполнена 13 октября 2026 года. Это зафиксированное состояние сервиса на дату проверки; его доступность впоследствии может измениться.

## Подтверждённая причина таймаута

В кабинете выдан адрес Telegram API `https://4100.api.green-api.com`. Запросы `getStateInstance` и `getSettings` к этому адресу не установили соединение с сервером. Node.js `fetch` завершился с причиной `UND_ERR_CONNECT_TIMEOUT`; отдельный запрос curl к корню этого хоста без ключа также завершился таймаутом подключения, без HTTP-ответа.

DNS-запись проверена: `4100.api.green-api.com` разрешается в `158.160.222.174`. Запрос с явно заданным IP, обходящий DNS, также не установил TCP-соединение. Отдельная проверка через сетевой интерфейс Wi-Fi вместо VPN получила тот же результат.

Независимое подтверждение — [официальная страница статуса GREEN-API](https://status.green-api.com/). Её публичные данные показывают:

| Компонент          | Состояние в момент проверки | Доступность за 13.10.2026 на момент проверки |
| ------------------ | --------------------------- | -------------------------------------------- |
| Instances 4100     | `danger` — недоступен       | 0.000%                                       |
| Notifications 4100 | `danger` — недоступен       | 0.000%                                       |
| Instances 7105     | `success` — доступен        | 100.000%                                     |

Снимок выбранных публичных данных с временем проверки находится в [api-status-2026-10-13.json](api-status-2026-10-13.json). Источник — endpoint, используемый самой страницей статуса: `https://status.green-api.com/api/getMonitorList/aq1V2h2ZyW?page=1`.

Следовательно, подтверждена недоступность назначенного кластера 4100. Внутреннюю техническую причину простоя может установить только GREEN-API. Это не доказательство неисправности всех их Telegram-серверов: кластер 7105 в тот же момент отвечал.

## Что исключено и что остаётся непроверенным

Формат запроса соответствует [официальной документации Telegram](https://green-api.com/telegram/docs/request-format/):

```text
GET {apiUrl}/waInstance{idInstance}/getStateInstance/{apiTokenInstance}
GET {apiUrl}/waInstance{idInstance}/getSettings/{apiTokenInstance}
```

Префикс `/v4` или `/v5` не требуется. Подменять адрес на 7105 для существующего ID нельзя: это другое подключение на другом кластере.

HTTP-ответа не получено, поэтому корректность ключа, авторизация Telegram и CORS для 4100 не подтверждены. Нельзя приписывать этот таймаут неверному токену или ошибке CORS: до HTTP-проверок запрос не дошёл.

Клиентские проверки выполняются отдельно с фиктивными ответами API. Они подтверждают поведение интерфейса и контракт запросов, но не реальную доставку. Для проверки отправки и ответа необходимо восстановление 4100 либо другое авторизованное подключение, выданное GREEN-API на работающем сервере.

MAX отсутствовал среди доступных способов создания подключения в использованном кабинете. Выбран Telegram, который разрешён исходным ТЗ. Это наблюдение о конкретном кабинете, а не утверждение об отсутствии MAX у GREEN-API вообще.
