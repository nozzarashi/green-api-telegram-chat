# Чат · GREEN-API

Минималистичный React-клиент для отправки и получения **текстовых сообщений MAX и Telegram** через GREEN-API. Чат по номеру телефона, входящие сообщения через HTTP long polling, статусы доставки, повтор отправки после ошибки и спокойный адаптивный интерфейс с привычной структурой мессенджера. Telegram выбран по умолчанию; MAX также поддерживается.

Это интеграция с реальным API. В обычной сборке нет демонстрационных сообщений или имитации ответов.

## Локальный запуск

Нужен **Node.js 22.12+** (ветка 22 LTS). В папке проекта:

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, обычно http://127.0.0.1:5173.

Production-сборка:

```sh
npm run build
npm run preview
```

Готовый `dist/` можно разместить на любом HTTPS-хостинге статических файлов. Приложению не требуется свой сервер. Ключи вводит пользователь; переменные окружения с секретами и ручное редактирование исходников не нужны.

## Как подключить свой мессенджер

1. Зарегистрируйтесь в [кабинете GREEN-API](https://console.green-api.com/) по своей почте. Создайте подключение **Telegram** или **MAX** на бесплатном тарифе **Developer**. В кабинете такое подключение называется «инстансом». Доступ к серверу работодателя или отдельный бэкенд для этого не требуется.
2. Подключите свой мессенджер по инструкции на странице подключения в кабинете. После авторизации скопируйте `apiUrl`, `idInstance`, `apiTokenInstance` в поля **«Адрес API»**, **«ID подключения»**, **«Ключ доступа»**. В списке **«Мессенджер»** выберите тот же тип. Пароль от мессенджера в поле ключа не вводится.
3. Нажмите **«Подключить Telegram»** или **«Подключить MAX»**. Приложение проверит состояние, тип и флаги уведомлений. Если приём выключен, явная кнопка **«Настроить приём сообщений»** включает уведомления и очищает Webhook URL. Это отключает прежний webhook и может вызвать перезапуск подключения до пяти минут; затем подключитесь повторно.
4. Создайте **«Новый чат»** по телефону получателя. Для MAX проверка телефона поддерживает РФ (`+7`) и Беларусь (`+375`). Для Telegram используйте международный номер с кодом страны. Российский номер без плюса, начинающийся с `8`, нормализуется в `7`.
5. Отправьте текст: **Enter** — отправка, **Shift+Enter** — новая строка. Лимит — **4000 для MAX**, **4096 для Telegram**. Получатель отвечает в обычном приложении мессенджера, ответ появляется в нашем чате.

Для полного теста нужен человек с выбранным мессенджером, согласный получить сообщение и ответить. Ему не нужен аккаунт GREEN-API. Поиск по телефону должен быть доступен: скрытый номер может дать отрицательный результат проверки даже при существующем аккаунте.

Если MAX отсутствует в вашем кабинете, можно проверить [прямую страницу тарифов MAX](https://console.green-api.com/instanceList/tariffs?messenger=v3). Эта ссылка не выдаёт доступ к тарифу: при отсутствии MAX выберите Telegram — исходное ТЗ прямо разрешает такую замену.

Один инстанс обслуживает один аккаунт мессенджера. Используйте один HTTP-потребитель очереди на подключение: другие программы могут забирать уведомления. Для работы чата нужны пустой `webhookUrl` и флаги `incomingWebhook`, `outgoingWebhook`, `outgoingAPIMessageWebhook`, `outgoingMessageWebhook`, `stateWebhook` со значением `yes`. Приложение проверяет их; настройка вызывается только по явной кнопке.

## Поведение и ограничения

- `checkAccount` получает постоянный **chatId выбранного мессенджера** по номеру. Отправка и сопоставление ответов используют этот ID, а не телефонный WhatsApp-идентификатор.
- HTTP 200 у `sendMessage` означает **«В очереди»**. **«Доставлено»** и **«Прочитано»** появляются только по уведомлению API.
- Получение последовательное: `receiveNotification → обработка → deleteNotification`. Также подтверждаются события неподдерживаемых типов, чтобы очередь продолжала двигаться. Повторно полученное сообщение не дублируется.
- После сетевого сбоя приём автоматически возобновляется с задержкой. При ошибке доступа приём останавливается; требуется переподключение.
- Отправка автоматически не повторяется: при таймауте сервер мог уже принять сообщение. Интерфейс объясняет эту неопределённость перед ручным повтором.
- Ключи, список чатов, черновики и история хранятся **только в памяти текущей вкладки**. После выхода или перезагрузки их нужно вводить заново. В ТЗ не требуется загрузка старой истории или постоянное хранение.
- Медиа, звонки, группы и поиск контактов вне списка текущих чатов не входят в задание. События медиа подтверждаются, но не отображаются.
- Клиент обращается напрямую к HTTPS API GREEN-API. Адрес ограничен официальными API-хостами; произвольному домену токен не отправляется. В коде нет аналитики, вывода ключей в лог, localStorage или сторонних CDN-скриптов.

## Архитектура

React + TypeScript (strict, noUncheckedIndexedAccess), Vite, CSS Modules. Дизайн проверен с ui-ux-pro-max. Button и Dialog собраны по подходу shadcn/ui: Radix UI и class-variance-authority, со стилями CSS Modules. Иконки — Lucide, шрифт Manrope поставляется локально. FSD без лишних слоёв:

```text
src/
  app/                         # запуск, глобальные токены, ErrorBoundary
  pages/chat/                  # композиция сценариев и сессия чата
  widgets/chat-workspace/      # список чатов, заголовок, история
  features/
    connect-instance/          # подключение и явная настройка уведомлений
    create-chat/               # проверка телефона и создание чата
    send-message/              # редактор сообщения
    receive-messages/          # отменяемый long-polling цикл
  entities/chat/               # события мессенджеров, reducer, дедупликация и статусы
  shared/
    api/                       # типизированный HTTPS-клиент, валидация ответов
    config/                    # профили MAX / Telegram и ограничения
    lib/                       # нормализация телефона
    ui/                        # переиспользуемые контролы
```

Слайсы предоставляют публичные `index.ts`. ESLint запрещает зависимости нижнего FSD-слоя от верхнего. Внешние JSON-ответы проверяются во время выполнения; типы не подменяют такую проверку. API-клиент принимает `fetch` для изолированных тестов. Reducer и polling не зависят от DOM.

## Проверки

```sh
npm run check         # TypeScript, ESLint, Prettier, unit-тесты, production build
npx playwright install chromium
npm run test:e2e      # браузерные сценарии с изолированным mock GREEN-API
```

Отдельно доступны `typecheck`, `lint`, `format:check`, `test`, `test:watch`, `build`. CI-файл `.github/workflows/quality.yml` запускает эти проверки и браузерные тесты.

Для установленного Chrome можно выполнить e2e без скачивания браузера. PowerShell:

```powershell
$env:PLAYWRIGHT_EXECUTABLE_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:e2e
```

Браузерные mock-тесты проверяют реальный UI и HTTP-контракт: подключение, создание чата, отправку, входящий текст, подтверждение очереди, повтор события, гонки echo/статуса/ответа отправки, ошибки и мобильную навигацию. Они **не доказывают доставку в настоящий мессенджер**. Финальная проверка доставки требует действующего аккаунта GREEN-API и отдельного получателя; вводите реальные ключи только в интерфейс.

## Соответствие ТЗ

| Требование                                   | Реализация                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| MAX или разрешённый Telegram через GREEN-API | MAX: `v3`, Telegram: `telegram`                                   |
| Только текст                                 | textMessage и extendedTextMessage                                 |
| Прототип web.max.ru                          | Две панели, нейтральный фон, синий акцент, пузырьки, адаптивность |
| Минимум функций                              | Подключение, новый чат, текст, получение, статусы, выход          |
| SendMessage                                  | POST `/waInstance{id}/sendMessage/{token}`                        |
| HTTP получение                               | GET receiveNotification + DELETE deleteNotification               |
| React                                        | React + TypeScript, компоненты и hooks                            |
| Вход по id/token                             | Форма подключения, apiUrl из кабинета                             |
| Создание чата по телефону                    | checkAccount → постоянный chatId мессенджера                      |
| Ответ получателя в чате                      | Polling, нормализация событий, reducer                            |
