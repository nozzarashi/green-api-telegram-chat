# MAX · GREEN-API

Минималистичный React-клиент для отправки и получения **текстовых сообщений MAX** через GREEN-API. Чат по номеру телефона, входящие сообщения через HTTP long polling, статусы доставки, повтор отправки после ошибки и адаптивный интерфейс по мотивам web.max.ru.

Это интеграция с реальным API. В обычной сборке нет демонстрационных сообщений или имитации ответов.

## Локальный запуск

Нужен **Node.js 22.12+** (ветка 22 LTS). В папке проекта:

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, обычно http://127.0.0.1:5173.

Production-сборка:

```sh
npm run build
npm run preview
```

Готовый `dist/` можно разместить на любом HTTPS-хостинге статических файлов. Приложению не требуется свой сервер. Ключи вводит пользователь; переменные окружения с секретами и ручное редактирование исходников не нужны.

## Как подключить MAX

1. Откройте [кабинет GREEN-API](https://console.green-api.com/). Создайте инстанс именно **MAX** и подключите к нему свой аккаунт MAX по инструкции сервиса. Вход в web.max.ru сам по себе не подключает GREEN-API.
2. На странице инстанса скопируйте **apiUrl**, **idInstance** и **apiTokenInstance** в соответствующие поля приложения. `apiUrl` берётся из вашего кабинета, например `https://3100.api.green-api.com`.
3. Для HTTP-приёма должен быть пустым `webhookUrl` и включены уведомления о входящих и исходящих сообщениях, доставке и состоянии аккаунта. Приложение проверит все нужные флаги. Если настройки не подходят, можно нажать **«Настроить приём сообщений»**. Эта явная операция отключает прежний webhook и включает уведомления; GREEN-API перезапустит инстанс, применение может занять до пяти минут. Затем подключитесь снова.
4. Нажмите **«Новый чат»**, введите номер получателя в международном формате. Проверка по телефону в MAX поддерживает РФ (`+7`) и Беларусь (`+375`). Привычное российское `8...` приложение преобразует в `7...`.
5. Напишите текст. **Enter** отправляет, **Shift+Enter** добавляет строку. Максимум — 4000 символов. Получатель отвечает в своём MAX, ответ появляется в чате.

Нужно, чтобы получатель был зарегистрирован в MAX и разрешал поиск по номеру. Используйте один HTTP-потребитель очереди для одного инстанса: другие программы, одновременно читающие эту очередь, могут забирать уведомления.

Для доставки и прочтения включите `outgoingWebhook` и `outgoingAPIMessageWebhook`. Для сообщений, отправленных из других клиентов MAX, включите `outgoingMessageWebhook`; для изменения состояния — `stateWebhook`. Кнопка настройки приёма включает все эти флаги.

## Поведение и ограничения

- `checkAccount` получает постоянный **MAX chatId** по номеру. Отправка и сопоставление ответов используют этот ID, а не телефонный WhatsApp-идентификатор.
- HTTP 200 у `sendMessage` означает **«В очереди»**. **«Доставлено»** и **«Прочитано»** появляются только по уведомлению API.
- Получение последовательное: `receiveNotification → обработка → deleteNotification`. Также подтверждаются события неподдерживаемых типов, чтобы очередь продолжала двигаться. Повторно полученное сообщение не дублируется.
- После сетевого сбоя приём автоматически возобновляется с задержкой. При ошибке доступа приём останавливается; требуется переподключение.
- Отправка автоматически не повторяется: при таймауте сервер мог уже принять сообщение. Интерфейс объясняет эту неопределённость перед ручным повтором.
- Ключи, список чатов, черновики и история хранятся **только в памяти текущей вкладки**. После выхода или перезагрузки их нужно вводить заново. В ТЗ не требуется загрузка старой истории или постоянное хранение.
- Медиа, звонки, группы и поиск контактов вне списка текущих чатов не входят в задание. События медиа подтверждаются, но не отображаются.
- Клиент обращается напрямую к HTTPS API GREEN-API. Адрес ограничен официальными API-хостами; произвольному домену токен не отправляется. В коде нет аналитики, вывода ключей в лог, localStorage или сторонних CDN-скриптов.

## Архитектура

React + TypeScript (strict, noUncheckedIndexedAccess), Vite, CSS Modules. FSD без лишних слоёв:

```text
src/
  app/                         # запуск, глобальные токены, ErrorBoundary
  pages/chat/                  # композиция сценариев и сессия чата
  widgets/chat-workspace/      # список чатов, заголовок, история
  features/
    connect-instance/          # подключение и явная настройка уведомлений
    create-chat/               # проверка телефона и создание чата
    send-message/              # редактор сообщения
    receive-messages/          # отменяемый long-polling цикл
  entities/chat/               # события MAX, reducer, дедупликация и статусы
  shared/
    api/                       # типизированный HTTPS-клиент, валидация ответов
    lib/                       # нормализация телефона
    ui/                        # переиспользуемые контролы
```

Слайсы предоставляют публичные `index.ts`. ESLint запрещает зависимости нижнего FSD-слоя от верхнего. Внешние JSON-ответы проверяются во время выполнения; типы не подменяют такую проверку. API-клиент принимает `fetch` для изолированных тестов. Reducer и polling не зависят от DOM.

## Проверки

```sh
npm run check         # TypeScript, ESLint, Prettier, unit-тесты, production build
npx playwright install chromium
npm run test:e2e      # браузерные сценарии с изолированным mock GREEN-API
```

Отдельно доступны `typecheck`, `lint`, `format:check`, `test`, `test:watch`, `build`. CI-файл `.github/workflows/quality.yml` запускает эти проверки и браузерные тесты.

Для установленного Chrome можно выполнить e2e без скачивания браузера. PowerShell:

```powershell
$env:PLAYWRIGHT_EXECUTABLE_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:e2e
```

Браузерные mock-тесты проверяют реальный UI и HTTP-контракт: подключение, создание чата, отправку, входящий текст, подтверждение очереди, повтор события, гонки echo/статуса/ответа отправки, ошибки и мобильную навигацию. Они **не доказывают доставку в настоящий MAX**. Финальная проверка доставки требует действующего аккаунта GREEN-API и отдельного получателя; вводите реальные ключи только в интерфейс.

## Соответствие ТЗ

| Требование                | Реализация                                                           |
| ------------------------- | -------------------------------------------------------------------- |
| MAX через GREEN-API       | MAX-инстанс, проверка `typeInstance === 'v3'`                        |
| Только текст              | textMessage и extendedTextMessage                                    |
| Прототип web.max.ru       | Белая боковая панель, синий акцент, фон чата, пузырьки, адаптивность |
| Минимум функций           | Подключение, новый чат, текст, получение, статусы, выход             |
| SendMessage               | POST `/waInstance{id}/sendMessage/{token}`                           |
| HTTP получение            | GET receiveNotification + DELETE deleteNotification                  |
| React                     | React + TypeScript, компоненты и hooks                               |
| Вход по id/token          | Форма подключения, apiUrl из кабинета                                |
| Создание чата по телефону | checkAccount → постоянный MAX chatId                                 |
| Ответ получателя в чате   | Polling, нормализация событий, reducer                               |
