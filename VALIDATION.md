# Проверка результата

Дата: 13 октября 2026 года.

## Пройдено

- `npm run check`: TypeScript strict, ESLint 10 (0 ошибок/предупреждений), Prettier, 46 unit-тестов, production-сборка Vite.
- `npm run test:e2e`: 18 сценариев проходят на production preview финального `dist/`, Chromium (установленный Chrome), с изолированными HTTP mock-ответами GREEN-API. React StrictMode дополнительно проверен в dev-прогоне.
- `npm ls --depth=0`: дерево зависимостей без ошибок. Версии зафиксированы в package.json и package-lock.json.
- npm audit при финальной установке: 0 найденных уязвимостей.
- Desktop/mobile скриншоты просмотрены; нет горизонтального переполнения, длинный текст переносится, список и чат доступны на мобильном экране.
- Независимое ревью API-контракта, lifecycle запросов, reducer, отмены, гонок статусов и настроек уведомлений.

## Проверенные сценарии

1. Подключение MAX-инстанса: проверки состояния и типа; ошибка авторизации и неверный мессенджер.
2. Создание чата по телефону: нормализация, запрос checkAccount, использование постоянного MAX chatId, неверный номер и отсутствие аккаунта.
3. Отправка точного текста, Enter/Shift+Enter, IME, лимит 4000, защита от повторного submit.
4. Получение обычного и расширенного текста, правильный порядок сообщений и DELETE точного receiptId.
5. Игнорирование медиа с подтверждением очереди; дедупликация при ошибке ACK.
6. Гонка ответа sendMessage, исходящего echo и статуса прочтения; сохранение read при поздних событиях.
7. Ошибка отправки, неизвестный результат, отсутствие автоматического повторного POST, ручной retry с предупреждением.
8. Ошибка доступа во время приёма; stateInstanceChanged, блокировка отправки и восстановление authorized.
9. Проверка всех обязательных флагов уведомлений. setSettings вызывается только после явной кнопки пользователя.
10. Выход и отмена polling/запросов, отсутствие сообщений от позднего ответа после выхода.
11. Мобильная навигация, модальное окно, фокус, перенос длинных строк, поиск, черновики.
12. Быстрые пустые ответы не создают busy loop; нормальный long polling не получает лишнюю задержку.

## Границы проверки

Реальные ключи GREEN-API не предоставлялись. Поэтому не подтверждены успешная авторизация в настоящем инстансе, доступ API с его `apiUrl` из конкретной сети, CORS успешного авторизованного запроса и доставка/ответ в реальном MAX. HTTP mock-тесты проверяют контракт и поведение приложения, но не заменяют этот финальный smoke-test.

Для live-проверки: подключите свой MAX в кабинете GREEN-API, введите данные в интерфейсе, создайте чат со вторым аккаунтом, отправьте текст и ответьте на него из MAX. После ответа проверьте его появление в интерфейсе. Инструкция — в README.md.

Скриншоты демонстрируют приложение с фиктивным собеседником и тестовыми сообщениями. Личные чаты из web.max.ru не включены в исходники или архив.
